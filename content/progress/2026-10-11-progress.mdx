# Build120 那天：把输入法从"还能用"拽回"信得过"

Build120 是这天的主角。之前很长一段时间，Codex 在解决输入法候选词排序问题：输入 `codex`/`wodecodex`，英文候选总排第二，中文译文却莫名其妙地被选走。几条线索穿插在一起，最初看上去像英文路径有问题，但顺着排查才发现，根因根本不在英文——是中文拼音解码、词库权重和自动组句质量这一整条链都有偏差。

## 一、把锅从英文挪回到中文

Codex 会话里有一段很关键的"自我纠偏"：原本以为是英文排序要拉回第一位，结果复现 `codex/code/gpt/api/task/python` 一串词后，问题非常一致——只要存在中文候选，英文原词就被踢出竞争；而解释竞争那一轮只接受中英混合的结果，纯英文走的是另一条"补充候选"路径。换句话说，英文候选从来没真正进入过正赛。

更深的发现是拼音链路本身。词库并没有收录"陈欧的新"这样的整条怪词，它是合法词条碎片临时拼出来的；而首字母简拼还在用普通 `derive`，没采用 Rime 专门给简拼设的类型和置信度惩罚，搭配评分也不够判断整句自不自然。于是思路被收回到一串顺序明确的验证与修正：简拼可信度 → 词频与搭配评分 → 自动组句质量。Build120 跑通后，`codex` 可以走 `c|o|de|x` 这种混合简拼全拼路径，例子 `chen|ou|de|xin` 在隔离环境回放里默认和提交都稳定落在"我的 codex"。

这天并不只是把英文摆正，而是逼着输入法承认自己那段中文拼音解析一直有偏差。

## 二、围绕 Build120 的小插曲

最让人哭笑不得的一节是 Build120 安装前后的来回验证。第一次提交 Build120 后，系统装上去跑了一遍隔离测试没问题，但截图仍显示旧结果。Codex 对照状态后承认：测试包只是验证过，主包其实还在 Build119 上没换装。补丁都在，只是没真正落盘。后来才补齐正式打包与安装，重启输入法、检查通过、回滚包保留，这才算真的把 Build120 立住了。

## 三、被压扁又被撑回来的 README

这天还做了一件看起来没 Build120 抓眼球的事：把 README 重写。

最开始的方向是"清理历史"，把 README 从 118 行压到 36 行，只留项目定位、主要入口和交付说明。这一刀切下去之后，Codex 自己复盘——现在算 README，但偏文档导航，产品介绍不够完整，第一次进项目的人不容易理解"这个东西到底是什么、能怎么用、为什么信它"。压得太狠了，必须找参考把产品介绍一块补回来。

参考了四个 GitHub 案例：MarkEdit 那种对编辑体验的清晰展示、Obsidian 生态那种"能力-插件-工作流"分层、Zed 那种"性能叙事+开发效率"的并置、Beeper 那种"产品定位 + 隐私承诺 + 一句话使用入口"的节奏。借鉴的点最终落地为：保留完整产品介绍、使用入门和开发入口；明确区分已实现、已验收和规划能力；版本号、测试数、小修复、Gate 历史不堆到首页里，全部去专项文档。
