# 日报管理后台：页面结构 V0.1

日期：2026-09-22。状态：文字结构设计，未实现页面或做视觉验收。

依据：[PRD](daily-report-admin-prd-v0.1.md)、[本机技术方案](daily-report-admin-technical-plan-v0.1.md)。用户要求采用开源后台前端，推荐以 [shadcn-admin](https://github.com/satnaing/shadcn-admin) 的布局和组件为基础。

## 1. 统一方向

Design Read：面向博客所有者的本机日报工作台，以表格、时间线和可追溯操作为主，沿用 shadcn-admin 的紧凑后台布局与语义主题。

默认浅色，提供深色切换；系统中文字体。采用模板的 Sidebar、Table、Badge、Tabs、Dialog、Sheet 和表单，不引入第二套组件库。进度用阶段表达，不加无依据的百分比。状态同时使用文字和图标，颜色仅作辅助。

本设计采用一个主方向，不做品牌重设计。公开博客的黑金展示风格不直接搬入数据密集的工作区。

## 2. 全局壳与路由

- 左侧：ajin-blog 标识、日报总览、异常待办；底部显示账号、主题和退出。
- 顶栏：当前页名称、数据更新时间、执行状态入口。
- `/reports`：默认首页；`/reports/:date`：详情；`/issues`：异常；`/login`：登录。
- 系统状态通过顶栏抽屉查看，不增加第四个主要业务页面。
- 日期筛选、结果筛选、分页保存到 URL；详情返回总览时恢复列表位置。
- 主要验收视口 1440×900、1280×800；较窄窗口收起侧栏，详情改为纵向布局。

## 3. 日报总览

以下是区域示意，括号为字段占位，不代表现场数据。

```text
侧栏       日报总览                         更新于（时间）  执行状态
           （观测中断/项目未挂载时的提示条）
           今日日报 （业务日期） （业务状态）
           当前阶段 / 阶段耗时 / 最近活动               查看详情
           （昨日或更早仍未完成的日报提示）

           日期范围      全部状态      仅看异常           重置
           日期 | 标题 | 状态 | 当前阶段 | 耗时 | 最近活动 | 操作
           ...
           共（数量）条                                  分页
```

今日摘要只显示当前最重要情况，不复制一排总数卡片。标题未产出时显示“尚未生成”。列表点击日期/标题进入详情；不以整行隐形点击作为唯一入口。异常优先提示但历史列表默认日期倒序。

空态：计划未到时“等待开始”；无有效素材“今日跳过”并提供原因；尚无导入数据“暂无记录”；数据读取失败显示“读取失败”与“重试”，不渲染为空列表。

## 4. 日报详情

```text
返回列表   （日期）日报       （状态）                 （可用主操作）
           （文章标题）       最近确认（时间）
           （阻塞原因 + 建议下一步，仅有异常时出现）

           生产进度                         产物与证据
           素材准备                         正文 | 封面 | 审稿 | 证据
           正文写作                         （选中内容预览）
           事实审稿
           修订复审
           封面简报
           封面生成
           视觉验收
           发布验证（可展开）

           运行历史：时间 / 来源 / 结果 / 耗时 / 关联恢复
           操作记录：提交者 / 动作 / 时间 / 结果
```

桌面时间线约占 1/3，产物约占 2/3；审稿内容较长时支持展开主区域。每个阶段显示开始/结束、耗时与阶段证据状态；`step completed` 后只有后续阶段启动或该节点业务结果事件证明门禁通过，才显示“已完成”与成功图标；只有调用返回但缺少后续验收证据时显示“调用已返回”。workflow 失败事件按失败原因或未完成的阶段尝试映射到具体业务节点，不单独展示整体流程节点；调用返回后的业务验收失败显示为“验收未通过”。点选后查看该次尝试详情，不能默认混用不同尝试的产物。

发布验证展开校验、提交、各远端推送、轮值、CI/部署、公网、终态回执。未记录的历史子步骤显示“未记录”；跳过修订显示“不适用”。

正文只读；封面保持 16:9 完整呈现并可放大；审稿按原句、问题、建议及结果组织。技术证据默认折叠，用户先看到可理解的错误摘要。

主操作每次最多一个：“重试阶段”“发起补跑”或“查看文章”；其余辅助动作放菜单。执行中显示“执行中”，重复提交禁用。没有恢复能力时给出具体原因，不呈现可点但必失败的按钮。

## 5. 异常待办

```text
异常待办                      全部类型 / 待处理 / 处理中
日期 | 问题 | 阶段 | 已持续 | 最新证据 | 处理状态 | 查看详情

选中异常抽屉：
  发生了什么
  影响和最后确认时间
  建议处理方式
  证据（折叠）
  处理意见（输入框）                         保存备注
  历史意见
```

处理状态是工作记录，不等于业务结果。保存备注不能关闭失败；系统发现符合条件的新证据后关闭异常，保留处理历史。列表无异常显示“暂无异常”；读取失败不能显示“暂无异常”。

## 6. 恢复与补跑弹窗

从后端取得 action-preview 后展示：业务日期、恢复起点、复用产物、影响范围、预检结论。执行范围用明确文字：“仅重试封面生成”或“从封面生成继续至发布”；后端仅返回实际支持的选项。

主按钮“确认执行”，次按钮“取消”。预检失败时保留原因，主按钮禁用。提交成功关闭弹窗并在详情显示命令“已排队”；toast 只写“已提交”，不能写“重试成功”。状态版本变化提示“状态已更新，请重新检查”。

补跑弹窗明确标出“将执行完整生产与发布流程”。未来日期、已完成日期与在途运行由后端拒绝；界面提前解释，不仅依赖按钮禁用。

## 7. 交互与验证要求

- 表格筛选、分页、返回、产物切换、异常备注和操作弹窗必须对应真实 API。
- 焦点可见，弹窗关闭后回到触发按钮；Tab 键可遍历，Esc 可关闭非提交中的弹窗。
- 轮询不得重置滚动、选中尝试、打开的产物或正在编辑的备注。
- 无模型过程流时不伪造打字动画；操作超时进入可核实状态，不自动再次提交。
- 登录过期保留当前路由，但不得把密码和敏感表单写到 URL 或 localStorage。
- 模板中的统计数字、销售图、用户头像和假数据全部移除；fixtures 仅用于测试环境并明确标记。
- 实现后检查三页的正常、空、加载、失败、离线和权限状态；文字结构通过不等于视觉或交互验收通过。
